# 数据查询与洞察

## 触发

用户要求查询模型或已有报表的数据、统计指标、筛选排序、比较分析，或基于数据生成洞察。报表创建/修改、模型建模进入 Part 1；定时查询和推送以 S1/S2 为主，本场景只承担其中的取数步骤。用户明确指定 API 时按 Part 1 核实调用，不重新规划业务路线。

## 外部智能体入口

本 Skill 面向 SmartBI 外部的通用智能体，不假设拥有 AIChat 注入的资源清单、Cookie、模型概览或浏览器当前筛选。“上下文”只指用户明确提供、本任务已核实或接口实际返回的信息。

复用已配置的 CLI/profile 和原版 Part 1 的接口调用框架；已知场景接口不重复搜索 operationKey。用户仅说“查询数据”而没有业务主题、指标、模型或报表线索时，只问一次要查什么业务或数据，不要求用户先给模型 ID、接口名或执行路径。用户补充业务主题后，第一步是查**业务资源目录**：当前环境已核实 `catalogtree.searchCatalogTree` 时，直接复用或先 `describe` 核实契约再调用；需要列举某类全部资源或搜索不可用时，按契约使用 `catalogtree.listCatalogElementsByResourceType` 等目录能力。不要先执行全量 `smartbi list`、搜索“模型相关操作”“listResource 操作”或遍历 Agent 清单；`list` 是接口注册表，不是模型目录。仅当目录 operationKey 在当前环境确实未知/不可用时，才按 Part 1 限定 `catalogtree` 域发现替代接口，避免把完整注册表输出交给模型。

用户给出名称、ID或链接时核实资源；只有业务需求时做有范围的资源搜索，结合类型、名称/别名、目录路径和口径选择。搜索响应先在本地排除字段、文件夹、任务、计划等不可直接取数项，再按名称/别名精确匹配、包含匹配、路径匹配的顺序排序并去重；只向用户展示少量最相关的可查询模型或报表。仍有多个会改变答案的强候选时再澄清，不能把服务端返回的上百个原始命中全部交给用户，也不能默认取第一项。目录不是模型，接口列表不是业务资源列表。定位后再根据实际模型字段或报表参数补齐会影响答案的指标、时间与粒度；用户说“当前报表/筛选”却缺少定位或筛选信息时，只澄清影响结果的缺项。链接不意味着可以读取浏览器登录态，也不将其他环境凭证发送到该地址。

用户明确说“基于某报表”或“查询电子表格、Web 电子表格、仪表盘、即席查询、透视分析等已有报表中的数据”时，先走已有报表问数。用户只给资源名称、别名或 ID、未说资源类别时，先通过当前环境目录核实实际 `type`：属于报表资源就走已有报表问数，属于数据模型或指标模型才走相应模型路径。不能因报表绑定模型、名称含“模型”，或问题只是简单汇总，就改用模型 MQL/SQL 代替报表结果；报表创建或修改仍走 Part 1。

拿到并核实 `AUGMENTED_DATASET` ID 后才请求 `datamodel.getDataModelTrees`；`modelIds` 必须包含实际模型 ID，不能把 `describe.suggestedCall` 的 `[]` 当作有效输入。旧指标模型和新指标模型按各自路径解析，不能把其目录 ID 塞入增强数据集字段树接口。普通直接取数不调用 `aichat.getAgentItems` 寻找模型；只有进入白泽/Agent 路径才查智能体。

## 执行路径

先按下表选择对象和执行方式，再按需加载对应参考文件。模型/报表已经定位，且对象、路径和范围均已明确时直接进入对应分支，不把 [query-routing.md](../references/query-routing.md) 设为每次查询的前置；资源未知、执行方式或范围有歧义、需要完整分页/TopN分母，或结果出现口径与完整性疑点时再读取它。

| 场景 | 路径 | 参考 |
|---|---|---|
| 列出/搜索可用模型或报表 | 模型资源按数据模型、新指标模型、旧指标模型分类发现；关键词需求定向搜索 → 核对类型与 ID → 展示有限候选 | [metric-model-query.md](../references/metric-model-query.md) |
| 数据模型取数 | `AUGMENTED_DATASET` 元数据 → MQL/只读 SQL → 校验数据 | [data-model-query.md](../references/data-model-query.md) |
| 新/旧指标模型取数 | 按资源类型解析可查询对象 → 对应模型元数据与只读接口 → 校验数据 | [metric-model-query.md](../references/metric-model-query.md) |
| 已有报表问数 | 明确基于已有报表，或名称/别名/ID 定位后核实为报表资源 → 必要定义与参数 → 只读查询/导出 → 校验 | [report-query.md](../references/report-query.md) |
| 复杂洞察或明确指定白泽 | 核实 Agent 与资源 → 会话执行 → 校验分析和交付物 | [sessions-and-logs.md](../references/sessions-and-logs.md) |

普通模型取数无需训练、白泽或会话；MQL 与 SQL 根据模型语义和已验证接口能力选择，不因错误自动切换。报表内置 Skill 仅是可核实后使用的能力，不是外部智能体运行前提。正式报告、归因、预测、行动建议及综合大屏按路由默认白泽；这里的“大屏”指新生成或综合分析，读取已存在的仪表盘数据仍走已有报表问数。用户明确直接取数/本地分析优先，已有数据排版或文件转换继续本地处理。

## 资源发现

“有哪些可用模型/报表”是目录枚举，不是字段树查询；“找某业务模型/报表”是目录搜索。以下是当前部署注册相应 operation 时的参考命令，首次使用先核对 `describe`，请求体写入临时 JSON 文件：

```bash
smartbi call catalogtree.listCatalogElementsByResourceType -d @resource-type.json --profile <PROFILE> --agent
smartbi call catalogtree.searchCatalogTree -d @resource-search.json --profile <PROFILE> --agent
```

枚举的类型随问句收窄：“数据模型”查 `AUGMENTED_DATASET`；“指标模型”查 `MT_MODEL` 与 `TABULAR_DATASET`；泛称“模型”，或在模型问数语境下说“数据资产”，才查三类并分组展示。明确指报表或数据源时走对应资源路径。具体取数差异见 [metric-model-query.md](../references/metric-model-query.md)。

当前环境的多类型合并枚举比逐类枚举少返回资源，不能未经对账就宣称完整。`MT_MODEL` 根 ID 不能直接用于增强数据集的字段树，须解析关联模型或专用能力；`TABULAR_DATASET` 使用自身元数据与查询接口。搜索时按当前契约提供关键词及权限过滤，省略 `purviewType` 后的空结果不一定代表资源不存在。精确别名搜索也可能命中同名目录，须核对类型与 ID。**MUST NOT** 用空 `modelIds` 的 `getDataModelTrees` 枚举资源。

## 场景内的执行约定

- 已授权只读取数无需逐接口再确认；模型查询、报表读取、元数据读取和结果文件下载不执行 Phase 3 的逐次确认。接口已核实则复用，仅补齐缺失信息。模型字段、报表参数或口径仍有影响答案的歧义才澄清。创建、修改、删除、发布、推送或启停服务端资源时，继续遵循主流程的写操作确认与授权范围。
- 元数据按需获取，不固定每次 Overview/CGI 探测；只在本任务复用有效信息，不建立模型/结果持久化缓存，不打包客户地址、资源ID或字段映射。
- 同来源同粒度查询合并；完整且范围适用的数据可用于追问，刷新或范围变化才再查询。不能从首批、TopN或聚合结果推导缺失总体。
- 普通取数目标是取齐明确范围和粒度；limit 是批量，TopN/样本才是需求上限。按当前契约判断预览、分页、截断或导出，文件格式不证明全量。同比、比率、累计值等不默认求和或平均。
- 只要求聚合和同比的混合指标仍走模型直接取数：按来源、过滤范围和聚合语义分成最少查询组，可加指标累计，时点指标取对应端点，期间平均与人均/人年等非可加指标按模型定义或已核实分子分母计算；全空输入及其本地派生结果保持空值。具体边界见 `query-routing.md`。
- 用户明确指定指标应使用的业务维度时，把它作为口径约束核对并落实到对应查询，不能用同名或相近的其他组织维度替代，也不能仅因返回了数值就判定完成。
- 跨来源维度切分指标时，按需核实模型关系及粒度；无可靠关系不猜测分组查询或 SQL 连接。互斥分组重复总体、分组合计异常或筛选未生效时暂停该结论；可加且分组穷尽时才以同范围总额对账，规则见 `data-model-query.md`。
- 输出业务答案、必要口径及结果范围，技术明细仅按排错/审计需要展示；不强制 CSV。结果异常按实际原因处理，不以转白泽或更换模型掩盖失败。

## 验证边界

不同模型、报表类型及部署能力须分别验证，不能用一次成功推定全部可用。只有实际执行路径及结果校验通过，才能声明当前对象与问句已完成；报表参数覆盖与业务数值对账不足时明确限制。
