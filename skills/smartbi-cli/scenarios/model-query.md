# 模型取数

## 触发

查询数据模型或新旧指标模型的字段、参数、成员及数据，执行统计、筛选、分组、排序、TopN、两期比较。模型创建或修改进入主技能通用流程；已有报表、模型修改等其他需求交回主技能，由实际保留的场景处理。

## 查询方式选择

用户明确指定取数方式时，优先按以下映射执行，不再自行比较或试探其他查询接口：

| 用户指定 | 使用接口 |
|---|---|
| MQL 取数 | `datamodel.queryDataByMql` |
| JSON 取数、结构化查询取数 | `tabularmodel.queryDataSetDataIterator` |
| SQL 取数 | `datamodel.queryDataBySql`，仅执行只读查询 |

这里的“JSON 取数”指结构化模型查询，不是“结果以 JSON 展示”；用户只要求 JSON 输出格式时，不据此更换查询接口。明确指定方式后，仍需核实模型类型、必要元数据与参数。接口不支持当前对象、元数据不足或执行失败时，说明具体限制；有业务歧义则澄清，未经用户同意不改用另一查询方式或白泽。补充元数据、合法分页和同路径内必要校验不属于切换方式。

用户未指定取数方式时，先核实模型类型与接口支持，再按下列规则选择：

```text
定位模型并核实类型
├── 数据模型 AUGMENTED_DATASET
│   ├── 逐条明细 → JSON 结构化查询
│   └── 汇总、分组、指标计算 → 优先 MQL
│       └── 所需能力无法表达 → 可保持原口径的 JSON 结构化查询
├── 指标模型 TABULAR_DATASET → JSON 结构化查询，核对当前部署与对象的实际支持
└── 新指标模型 MT_MODEL → 定位关联可查询模型，再按其实际类型选择
```

- **明细**指一行对应用户要求的一条业务记录，如订单行或交易记录；保留记录粒度，不自动聚合或去重。**汇总**指按维度统计指标，如各区域销售额。“查数据”本身不等于明细；先结合问句和模型确定所需粒度，仍有影响答案的歧义时澄清。
- JSON 使用 `tabularmodel.queryDataSetDataIterator`，同时承担明细与汇总。MQL 使用 `datamodel.queryDataByMql`。SQL 使用 `datamodel.queryDataBySql`，仅在用户明确指定 SQL 时采用，可表达明细或汇总，不作为默认或失败兜底。
- 已确认当前 MQL 无法表达所需排序、嵌套计算或交叉汇总，而 JSON 可等价执行时，直接选择 JSON，无需先试错 MQL。普通升降序仍可用 MQL 的 `sort`；同比等也须先核实已有能力，不能仅凭“排序”“同比”“复杂计算”等词切换接口。
- 转 JSON 须保持指标公式、筛选、时间、粒度和结果范围；不能用近似算法或不同分母代替原需求。权限、数据源、服务异常、字段未核实或业务歧义不属于 MQL 能力不足，不触发换路。无法确认等价时说明限制或澄清；用户明确指定 MQL 时不自动转 JSON。

## 最短执行链

1. 区分“只看字段/参数”和“实际取数”。模型身份已核实时复用；未知时按下面的加载条件定位，不遍历接口或 Agent。
2. 按[模型查询参考的统一元数据规则](../references/model-query/model-query.md#统一入口与补充条件)获取定义：普通查询或字段/参数清单用 `tabularmodel.getSimpleDataSet`；需要完整计算、时间维 ID、参数默认配置等信息时用 `tabularmodel.getDataSet`。已有充分信息直接复用；只看清单时作答后结束。
3. 实际取数：按本文件选择接口，只读取对应的 [JSON](../references/model-query/model-query.md#结构化查询json)、[MQL](../references/model-query/model-query.md#mql) 或 [SQL](../references/model-query/model-query.md#sql) 小节，根据已确认的定义构造请求。三者共用上述元数据规则，不分别试探元数据接口，也不先执行三个查询示例再挑结果。
4. 按接口结构核对字段映射、筛选、粒度、数值和结果范围，继续必要分页后交付。表头异常、全空与已有证据矛盾等情况进入模型查询参考的“执行与结果校验”，不交付猜测结论。普通模型取数不依赖训练、白泽会话或 Python。

## 补充加载条件

| 当前缺什么 | 加载什么 | 补齐后做什么 |
|---|---|---|
| 模型身份或类型未核实 | [公共资源发现](../references/common-core/resource-discovery.md) | 取得真实模型 ID、类型后回到本场景，不重复搜索 |
| 模型类型映射、字段、成员、参数或接口请求结构 | [模型查询参考](../references/model-query/model-query.md)的对应小节 | 补齐本次所需定义；已有充分信息不重新取元数据 |
| 时间角色、同比/比率、非可加指标、跨来源关系不明确 | [模型语义](../references/model-query/query-semantics.md) | 核对口径；仍有影响答案的歧义先澄清 |
| 满页、预览、截断、零行原因或完整性不明 | [公共结果规则](../references/common-core/query-results.md) | 按选定接口的分页与返回结构确认范围，不更换业务路径 |
| 需要下载或读取文件 | 由主入口确认已保留公共文件能力，再按其参考索引加载文件说明 | 下载、回读并核实内容；未保留时说明限制，纯接口数据不加载文件工具 |

精简定义、完整定义及成员信息的使用条件统一在模型查询参考中维护；字段树不能代替模型参数和完整定义。普通模型取数不调用 `aichat.getAgentItems` 寻找模型。

## 边界

混合累计、时点、平均与比率但只要求聚合和同比时仍属直接取数，按语义拆成最少查询组。同一个查询表达式最多执行一次及一次有元数据依据的修正；仍有字段、成员或口径歧义时向用户澄清。正常分页、已确认的独立查询组及必要总计核对不算修正试错；权限、服务或明确不支持的问题按实际原因报告。所需参考按上表加载，不把全部文档或校验清单作为每次查询的前置。
