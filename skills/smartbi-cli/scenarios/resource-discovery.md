# 模型与报表资源发现

## 触发

用户需要查找或列举 SmartBI 资源时进入本场景。根据用户意图和当前接口能力选择搜索或列举，不按固定问句匹配。模型、报表等仅为资源类型示例，不构成类型白名单；其他类型按当前目录契约识别，后续操作由主入口处理。仅发现资源时不执行数据查询。

## 搜索或列举

| 用户需求 | 接口与参数 | 处理方式 |
|---|---|---|
| 明确资源名称或别名 | `catalogtree.searchCatalogTree`，`name` 为资源名称，`queryMode: EXACT`，`matchField: ANY` | 精确匹配后核实类型；未命中且可能是简称时，才放宽一次模糊搜索 |
| 业务关键词或范围线索 | `catalogtree.searchCatalogTree`，`name` 为关键词，`queryMode: FUZZY` | 直接模糊搜索，不先做精确匹配；结果过多时结合类型、名称和目录收窄 |
| 查看某类资源清单 | `catalogtree.listCatalogElementsByResourceType`，按实际资源类型传 `type` | 返回当前账号可见资源，分类整理；不先搜一个关键词 |

搜索的 `purviewType` 按用户需求和当前契约明确传入；通常查看可见资源用 `REF`，明确要求读取权限时用 `READ`，不能把可见直接等同于可取数。类型枚举接口当前只接受 `type`，由服务端按当前身份过滤可见资源，不虚构关键词、权限或分页参数。

用户提供 ID 或链接时，先从已有信息核实目标环境与资源身份；能够直接定位就不强制转成名称搜索。名称、关键词、资源类型、目录范围和权限均来自用户要求或已核实上下文，不将任何示例值写成固定默认值。

## 结果处理

1. 已核实资源身份可直接复用；否则按上表选择一次搜索或列举，已知接口不重新发现 API。
2. 按真实资源类型排除同名目录、字段、任务等非目标项；搜索结果从 `catalogElement` 取 ID、名称、别名与类型，从 `aliasPath` 获取目录线索。枚举结果是简版节点，不假定含完整路径。
3. 唯一明确匹配直接使用；多个强匹配会改变后续答案时，展示少量名称、类型和目录，请用户区分，不让用户识别技术 ID，也不静默选第一项。
4. 只找资源时返回清单后结束。需要继续取数时，将已核实资源交回主入口，按实际类型进入已保留场景，不重复搜索。

## 加载条件与边界

类型映射、权限或匹配仍不清楚时读取[公共资源发现规则](../references/common-core/resource-discovery.md)，不加载模型、报表或白泽执行参考。已确认契约直接调用，首次未确认时只核对对应操作。

枚举结果多时本地整理、分批展示；服务端响应是否完整按当前契约和实际返回核实，展示首批不等于只找到首批。补目录只用于实际消歧，不为每个资源额外读取路径或元数据。未找到只表示当前环境、权限与搜索条件下无匹配，不断言资源不存在。

资源发现不依赖取数模块。未安装目标执行场景时明确能力边界；目录可见不保证报表或模型的数据查询成功。
