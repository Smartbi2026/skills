# 已有报表问数

## 触发

基于已有电子表格、Web 电子表格、仪表盘、即席查询或透视分析查看、统计、解读数据；资源名称或 ID 经核实为报表类型时也走本场景。创建或修改报表进入主技能通用流程。

## 执行

1. 已知报表沿用已核实身份；未知时走 [公共资源发现规则](../references/common-core/resource-discovery.md)，核对同名资源与类型。
2. 按 [报表问数参考](../references/report-query/report-query.md) 获取必要元数据与参数，落实用户指定筛选。
3. 按当前接口与报表能力只读查询或导出；读取实际数据及工作表，核对参数效果、统计口径与完整性。
4. 返回基于该报表的结果、有效筛选与范围；空文件或仅表头须核实筛选和来源状态；确认无记录时返回该范围无数据，不因零行盲目重试或切换模型。

用户明确说“基于某报表”或“查询电子表格、Web 电子表格、仪表盘、即席查询、透视分析等已有报表中的数据”时，先走已有报表问数。用户只给资源名称、别名或 ID、未说资源类别时，先通过当前环境目录核实实际 `type`：属于报表资源就走已有报表问数，属于数据模型或指标模型才走相应模型路径。不能因报表绑定模型、名称含“模型”，或问题只是简单汇总，就改用模型 MQL/SQL 代替报表结果；报表创建或修改仍走 第一部分。

## 边界

外部智能体没有页面预选资源、浏览器登录态或当前筛选，缺项只澄清会影响结果的信息。报表绑定模型不证明两者结果等价，只有用户明确要求基于底层模型继续分析时才进入模型路径，不能用模型结果替代报表结果。读取已有仪表盘不因“大屏”字样自动转白泽；后续复杂洞察交回主技能选择已保留的分析场景；未包含该能力时明确边界。共用结果规则见 [查询场景约定](../references/common-core/query-results.md)。

## 接口与加载条件

已知报表 ID 时，核对 `report.getReportMetadata` 当前契约后按 ID 读取元数据；不要为可选类型先枚举所有报表类型。需要数据且采用当前已确认导出能力时，使用 `report.exportReport`，不逐接口试读。目标环境缺少相应能力时先说明缺口，不将导出失败直接解释为资源不存在。

- 报表未定位：只加载公共资源发现规则。
- 参数、工作表、导出请求或报表类型映射不清：加载报表问数参考对应小节，已有契约和定义直接复用。
- 实际返回文件：加载文件处理规则；范围、截断或零行含义不明：加载公共结果规则。
- 用户要求内置白泽或基于底层模型分析：先按报表参考核实外部调用契约或口径等价，并由主入口选择实际保留模块；不同时加载所有分支探测。
