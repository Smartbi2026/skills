# 定时任务与计划

## 触发与分支

创建周期执行任务，或查看、修改、暂停、恢复、删除已有任务与计划时使用本场景。即时取数由主入口选择模型或报表场景；发送通知只有用户明确要求时才加入。

| 用户目标 | 最短处理 |
|---|---|
| 查看已有任务或计划 | 定位实际对象，读取所需状态、内容和时间后回答 |
| 改时间、暂停或恢复计划 | 回读现有计划 → 按当前契约修改目标字段或状态 → 回读核实；不生成业务脚本 |
| 修改任务内容 | 读取现有任务 → 只修改授权内容 → 必要时注入脚本 → 更新并回读 |
| 创建任务及计划 | 按下方创建链执行；已有且适用的任务直接复用 |
| 删除任务或计划 | 核实对象、绑定关系及删除范围，按当前契约和授权执行并确认结果；不连带删除其他对象 |

## 创建链

1. 明确任务内容、时间、目录与是否启用；仅澄清影响执行的缺项。用户要求“先保存、不启用”时，目标状态为停用；只要求创建而无法确定是否应立即启用时先保存停用并说明状态。
2. 由主入口组合已保留的模型取数、报表问数或消息发送能力，复用其字段、口径和接口选择。未包含所需能力时说明限制，不因现成 MQL 模板改变用户指定方式。
3. 核实当前环境和脚本凭证来源，按已选业务接口准备脚本；使用完整请求模板和注入工具后创建任务。脚本生成、注入与创建顺序执行。
4. 用 `scheduletask.getTaskById` 回读任务内容与类型，通过目录接口核实所属位置；不一致则停止后续创建。
5. 按当前契约创建计划，绑定已确认任务和时间，初始 `actived=false`；回读计划核对绑定、时间、目录及停用状态。
6. 用户要求启用且授权涵盖该操作时，用 `scheduletask.changeScheduleActiveStatus` 设置目标状态，再用 `scheduletask.getScheduleDtoById` 回读。要求停用或先保存时跳过激活；修改已有计划时保留未要求变更的状态。
7. 返回任务和计划的实际状态。创建或回读成功不等于已实际运行；用户要求试运行时才在授权范围内执行并检查日志，发送结果按消息场景判断。

## 按需加载

- 任务更新和脚本注入：读取[任务实现](../references/scheduled-tasks/task-execution.md#修改已有任务)的对应小节。
- 创建计划、调度参数和状态回读：读取[计划请求](../references/scheduled-tasks/task-execution.md#创建计划)及回读小节，不加载取数脚本。
- 已选 MQL 且需新增或修改服务端脚本：加载[Rhino 模板](../references/scheduled-tasks/rhino-script-template.md)。JSON/SQL、报表或 ETL 使用已选接口契约，不套 MQL 模板或猜执行方法。
- 脚本新增或修改时使用 `scripts/scheduled-tasks/inject-script.mjs`，从 Skill 目录解析绝对路径；纯计划管理不加载注入工具。
- 消息、接收人和送达检查由主入口组合消息模块；任务配置不能代替发送授权。

已核实的接口和对象直接复用；缺少操作契约才核对 describe，未知操作使用公共发现流程。重试、请求清理和前置依赖统一遵循公共调用规则。
