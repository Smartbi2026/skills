# 模型与报表资源发现规则

用于当前环境的资源身份和可见性核实，不执行模型或报表数据查询。

复用已配置的 CLI/profile 和通用接口调用框架；已知场景接口不重复搜索 operationKey。用户仅说“查询数据”而没有业务对象、指标、模型或报表线索时，只问一次要查什么业务或数据，不要求用户先给模型 ID、接口名或执行路径。用户补充业务对象或范围后，第一步是查**业务资源目录**：当前环境已核实 `catalogtree.searchCatalogTree` 时，直接复用或先 `describe` 核实契约再调用；需要列举某类全部资源或搜索不可用时，按契约使用 `catalogtree.listCatalogElementsByResourceType` 等目录能力。不要先执行全量 `smartbi list`、搜索“模型相关操作”“listResource 操作”或遍历 Agent 清单；`list` 是接口注册表，不是模型目录。仅当目录 operationKey 在当前环境确实未知/不可用时，才按通用流程限定 `catalogtree` 域发现替代接口，避免把完整注册表输出交给模型。

用户给出名称、ID或链接时核实资源；只有业务需求时做有范围的资源搜索，结合类型、名称/别名、目录路径和口径选择。搜索响应先在本地排除字段、文件夹、任务、计划等不可直接取数项，再按名称/别名精确匹配、包含匹配、路径匹配的顺序排序并去重；只向用户展示少量最相关的可查询模型或报表。仍有多个会改变答案的强候选时再澄清，不能把服务端返回的上百个原始命中全部交给用户，也不能默认取第一项。目录不是模型，接口列表不是业务资源列表。定位后再根据实际模型字段或报表参数补齐会影响答案的指标、时间与粒度；用户说“当前报表/筛选”却缺少定位或筛选信息时，只澄清影响结果的缺项。链接不意味着可以读取浏览器登录态，也不将其他环境凭证发送到该地址。

“有哪些可用模型/报表”使用类型枚举；用户明确提供名称/别名时用精确搜索，业务关键词直接用模糊搜索。精确搜索未命中且可能为简称时才放宽一次，不对所有关键词先精确再模糊。搜索或列举的选择统一由资源发现场景决定，本文件只补充类型、返回结构与权限边界。以下是当前部署注册相应 operation 时的参考命令，首次使用先核对 `describe`，请求体写入临时 JSON 文件：

```bash
smartbi call catalogtree.listCatalogElementsByResourceType -d @resource-type.json --profile <PROFILE> --agent
smartbi call catalogtree.searchCatalogTree -d @resource-search.json --profile <PROFILE> --agent
```

枚举的类型随问句收窄：“数据模型”查 `AUGMENTED_DATASET`；“指标模型”查 `MT_MODEL` 与 `TABULAR_DATASET`；泛称“模型”，或在模型问数语境下说“数据资产”，才查三类并分组展示。明确指报表或数据源时走对应资源路径。三类资源的取数接口不同，目录枚举只负责核实身份与类型。

枚举多类模型时分别按类型查询；如使用多类型合并结果，应先核对是否完整。`MT_MODEL` 根 ID 不能直接用于增强数据集的字段树，须解析关联模型或专用能力；`TABULAR_DATASET` 使用自身元数据与查询接口。搜索时按当前契约提供关键词及权限过滤，省略 `purviewType` 后的空结果不一定代表资源不存在。搜索命中项的资源 ID、类型可能位于 `catalogElement` 内，应从该对象核实；精确别名搜索也可能命中同名目录。不得用空 `modelIds` 的 `getDataModelTrees` 枚举资源。



## 类型边界

| 资源 | 目录类型 |
|---|---|
| 数据模型 | `AUGMENTED_DATASET` |
| 新指标模型 | `MT_MODEL` |
| 旧指标模型 | `TABULAR_DATASET` |

报表类型按当前环境目录与契约核实，常见电子表格、Web电子表格、仪表盘、即席查询和透视分析均属于报表候选。目录可见不保证有数据、查询接口可用或当前问句可执行。资源类型与查询接口中的模型类型、会话选中资源类型各有用途，不能混用。
