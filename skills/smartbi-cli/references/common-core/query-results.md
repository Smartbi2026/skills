# 查询共用规则与结果处理

适用于查询结果的范围、交付及执行环境；不负责选择业务场景，也不要求加载具体业务模块。模型指标计算和关联语义由模型取数模块负责，报表与服务端分析保持各自来源口径。

## 上下文、授权与复用

- 只使用用户提供、本任务核实或接口返回的上下文，不假设外部智能体有白泽注入资源、Cookie、浏览器筛选或预选模型。
- 已授权的只读查询、元数据和文件下载不逐接口确认；只澄清影响答案的歧义。创建、修改、发布、发送和启停等仍遵循主文件授权规则。
- 当前环境、身份与定义仍适用时复用已核实契约和元数据；完整结果可用于匹配范围的追问。字段或范围变化时按需补充，不将 TopN、首批或聚合结果当作完整明细。
- 按用户指定业务维度落实口径；模型指标、时间和关联算法由模型模块说明。结果异常先诊断，不靠换模型或转白泽掩盖。
- 交付业务答案、来源、条件、粒度及完整性；技术明细仅按排错或用户要求展示。不同模型、报表与部署分别核实，不从一次成功推定全部可用。

## 默认取数范围

- 普通“查询XXX数据”以取齐用户已明确条件与粒度下的结果为目标，不要求额外说“全部”。汇总问题只需完整汇总结果，不拉底层明细；没有明确条件且上下文也无法确定时，只澄清会影响答案的范围，不擅自补成全历史或全字段。
- `limit` 是单次批量。未满批且无服务端截断迹象时校验后结束；满批且无可靠结束证据时，按固定页长和稳定排序继续，直到短页/空页等结束证据成立。不要仅提示“可能截断”就把普通查询当作已经完成，也不为每页重复询问。
- 用户明确“前N条”“TopN”“抽样看看”时，N才是需求上限；满足该范围后停止，不因满N行再取下一页。TopN必须按目标指标排序，必要时加稳定次排序；若还问全体占比或总体合计，另保证分母完整，不能用TopN合计代替。
- 已有完整数据能回答时直接复用，不必为了验证是否还有数据重新请求。未知规模不先固定增加COUNT调用；已知适中规模优先一次取齐，不能以每次都分页作为最简路径。
- 若实际响应大小、查询耗时或运行环境容量表明继续获取不合适，保留已取数据，说明已取范围及未完成原因，再选择缩小范围或受支持的完整导出方式；不能静默停在某个内部行数上限，也不能无界提高limit。文件查询同样必须核对范围，文件格式本身不证明全量。
- 展示可以只给摘要或部分预览，但要区分“已取齐、仅预览N行”和“只取得N行、尚未取齐”。不要为把全表塞进对话而制造重复调用；需要完整交付时采用合适的本地文件或分批展示。

## 可移植执行

复用 npm 全局 CLI 和 profile，不写死地址、桌面客户端目录或 APPDATA。Shell 解析 smartbi；Windows 子进程从 PATH 解析 smartbi.cmd。请求用系统临时目录并在 finally 清理，结果放用户工作目录，Skill 目录不写入缓存/业务数据。Python/pandas 仅按文件读取或转换需要加载，不作为 MQL 调用前置。

不新增模型元数据、查询结果或失败记录的持久化缓存，不打包项目地址、凭证、资源ID、字段映射或测试产物；同一任务仅复用上下文中已确认的信息，环境/身份/字段变化时重新获取。CLI 自身的 API 注册表缓存由 CLI 管理，不作为 Skill 自带数据或客户配置。字段错误先检查元数据，不按报错候选猜业务映射。网络/数据源/权限错误按实际原因报告，重试遵循主技能 的幂等规则。

同一环境、同一任务已经证实失败或数值异常的能力/字段组合，保留失败原因和影响范围；后续同类问句复用该诊断，直到相关定义、版本、权限或输入发生变化。不要重复执行相同失败探测，也不要把单模型结论推广为其他模型的永久限制。

## 结果与状态

- 同时检查 CLI 状态、HTTP 状态和业务 `success/error`；HTTP 200 不能代替业务成功。读取文件须核对内容、范围和实际格式，文件后缀不证明完整性。
- 预览、分页和截断按当前契约核实；结果短于批量不一定代表完整。需要区分“已取齐但只展示部分”和“尚未取齐”。
- 已确认筛选生效、来源正常且实际无记录时，可以返回“该范围无数据”。零行不等于错误，空文件、仅表头或空字段树也不能单独证明业务范围无数据。
- NULL、空字符串和数值零分开处理；展示为空不证明实际值为空字符串。标识编码保留前导零，金额、比率和平均值按返回精度及明确口径处理。
- 原生数据流、HTTP分块和客户端逐页展示是不同能力；不能为流式展示引入额外业务流程。
- 技术成功不代表业务正确：核对筛选、时间范围、字段、粒度、必要统计与来源口径。存在疑点时补最少验证，不能把完整回归矩阵变成每次查询前置。
