# `call` 参考

本文件为 **SmartBI CLI Skill** 的附属参考；流程要求以 `SKILL.md` 为准。

**用途**：第三阶段（Execute）— 在已明确 `operationKey` 与参数来源的前提下发起 HTTP 调用。参数与 body **必须与** `describe` 中的 `callParameterPlan` 与 `requestBodySchema` 一致；可通过已授权只读操作取得的技术值自行核实；仅业务含义仍有歧义时向用户确认。

自动化流程默认优先使用 `--agent`；仅在下游明确要求单行 JSON 时使用 `--json`。

## 参数构造依据（文档优先，schema 兜底）

构造每个字段的值时，按以下优先级确定取值来源：

1. **用户输入或上下文已知事实**：用户在对话中已明确提供的值
2. **文档内容**（优先）：第二阶段 加载的文档中定义的合法枚举值、字段语义、组合约束、完整示例
3. **`requestBodySchema`**（兜底）：文档不可用或未覆盖时，以 schema 的字段类型约束、必填/可选为准
4. **`callParameterPlan`**：CLI 标志映射
5. **`suggestedCall`**：仅供参考的命令模板，不应直接复用其占位值

文档用于理解语义；结构、必填、类型或枚举与当前接口契约冲突时，以当前契约为准，业务语义冲突继续核实；不应仅看字段名猜测语义或编造值。

## 命令形式

```bash
smartbi call <operationKey> --profile <name> [选项...] [--json|--yaml|--agent]
```

## 常用选项


| 选项                      | 说明                          |
| ----------------------- | --------------------------- |
| `--profile <name>`      | 环境名；**所有命令一律带**（环境选择见 `references/common-core/profiles.md`） |
| `-d, --data <json>`     | JSON 请求体；**必须**使用 `-d @file.json`（将 JSON 写入文件后传入 @ 路径） |
| `-F, --form <k=v\|k=@file>` | multipart 字段（可重复）      |
| `--path <k=v>`          | 路径参数（可重复）                   |
| `--query <k=v>`         | 查询参数（可重复）                   |
| `--header <k=v>`        | 请求头（可重复）                    |
| `--timeout <ms>`        | 单次响应超时，纯十进制正整数毫秒，覆盖 profile timeoutMs；连接建立阶段约10秒的超时不由该参数控制 |
| `--dry-run`             | 仅打印请求预览，不发送网络请求             |
| `--idempotent`          | 允许对**写请求**按策略自动重试（须业务上可幂等）  |
| `--stream`              | 流式响应（如 SSE）                 |
| `--stream-format <fmt>` | 流式解析提示（保留/按实现）              |
| `--max-events <n>`      | 流式最多处理事件/块数                 |
| `-o, --output <path>`   | 二进制响应写入文件                   |
| `--stdout`              | 二进制响应写入标准输出                 |
| `--refresh`             | 强制刷新 registry 缓存            |
| `--json` / `--yaml` / `--agent` | 与 list/search/describe 相同约定 |
| `--config <path>`       | 配置文件路径                      |


## 与 `describe` 的对应关系

- `--path` / `--query` / `--header`：与 `callParameterPlan` 中各分组的 `name`、`cli` 一致。
- `-d`：在 `body.kind === json` 且 `consumes` 含 JSON 类类型时使用；**必须**使用 `-d @file.json`，JSON 内容须满足 `requestBodySchema`。
- 不得使用内联 JSON（如 `-d '{"k":"v"}'` 或 `-d "{\"k\":\"v\"}"`）。
- `-F`：在 `body.kind === multipart` 时使用；文件字段遵循 schema 中 `format: binary` 等约定。
- **无 body**：`body.kind === none` 时不要强行带 `-d`/`-F`（除非 OpenAPI 另有约定且已在 describe 中体现）。

## 临时请求体文件（`-d @data.json` 等）的生命周期（必须）

- 由代理/自动化**为本轮 `call` 新建**的 JSON 文件（例如 `data.json`、`*-body.json`）：在 **`smartbi call` 整段流程结束**后（含成功、失败、dry-run、重试耗尽）**必须** 删除该文件，除非用户**明确要求保留**（例如留档审计）。
- 不得 在任务收尾后长期遗留含业务参数或可能含敏感字段的临时 JSON；优先写入系统临时目录，或仓库内已 `.gitignore` 的路径，降低误提交风险。
- 若 `-d @` 指向的是**用户已有文件**（非本轮创建），不得 擅自删除。

## 成功判定与观测字段

CLI 2.2.0会将HTTP成功但顶层success:false识别为 `BIZ_ERROR`（exit 4），流式响应同样检查。此类业务失败不重试，按结构化错误中的 `details.upstreamMessage`、`upstreamErrorCode`、`upstreamBodyPreview` 定位。退出码0仍不能证明嵌套工具、会话轮次、交付范围或业务答案正确，保留下述结果校验。

成功JSON中常关注：

- `status`：HTTP 状态码
- `tid`：追踪标识（若存在）
- `data`：业务载体；失败或业务错误时可能含 `data.success`、`data.error`（与 第四阶段 诊断字段一致）

具体形状以当前安装 CLI 的 `smartbi call --help`、目标 operation 的 `describe` 响应和实际实现为准；Skill 不捆绑版本固定的 schema 文件。

创建或修改资源后，按该资源的读取接口回读目标字段，确认变更已生效再向用户报告成功。HTTP 200、`success=true` 或更新接口返回 ID 只证明调用被接受；若不同读取接口的结果冲突，按字段说明各自的回读结果，不把整个更新判为成功，也不继续依赖未确认的新值执行后续操作。

## 重试与幂等（与 CLI 实现对齐）

- **写方法**：`POST`、`PUT`、`PATCH`、`DELETE` 视为写请求。
- **是否允许写请求自动重试**：仅当 `--idempotent` 传入，或 describe 元数据中 `idempotent === true`（通常来自 OpenAPI `x-idempotent`）时，写请求才可进入与读请求相同的重试路径；否则写请求 **最多尝试 1 次**。
- **重试次数**：允许重试时，最多 **3 次** 尝试（含指数退避与抖动）。
- **可因 HTTP 状态触发的重试**（在仍有剩余次数时）：**429**、**502**、**503**。
- **网络类错误**：在 CLI 判定为可重试的网络超时/错误时，同样可在上述次数内退避重试。
- **代理义务**：不得对非幂等写请求假设可安全重放；须满足主技能 的幂等门控后再依赖 `--idempotent` 或元数据 `idempotent`。

## 前置操作与依赖

请求缺少技术值时，先区分能通过接口取得的值与必须由用户决定的业务范围。资源 ID、当前用户等可通过已授权接口核实的值由智能体取得，不要求业务用户手动查接口。

1. 默认在当前任务内完成前置操作，继承已选场景、环境、授权与已确认契约，不重新发动整个 Skill。已有有效结果直接复用。
2. 只在宿主支持且独立操作确有收益时委派子任务；不要求所有平台提供独立子智能体工具。委派不能扩大授权或改变已选业务路径。
3. 前置操作有依赖时顺序执行；失败时说明受影响的父操作并停止，不把占位值填入请求。创建等写操作仍须取得对应授权。
4. 同一调用链内，同一 operationKey 与相同参数意图的前置结果只取一次。逻辑依赖深度最多 3 层（原操作为 0），每个操作最多 5 个直接前置步骤；这些上限不限制正常分页。
5. 达到上限或必要信息无法取得时，说明缺项、已完成结果和停止原因。业务歧义向用户澄清；技术权限或接口问题报告实际原因，不让用户猜技术参数。

这里的“前置操作”是业务调用依赖，不等同于创建新智能体或新会话。

## 输出契约（机器校验）

- 当前安装 CLI 的 `smartbi call --help` 和目标 operation 的 `describe` 响应

与 CLI 行为或 schema 不一致时，以**当前安装的 `smartbi call --help` 与目标接口实际契约**为准。

## 业务语义抽取

当用户未显式提供接口名时，先抽取以下槽位：

| 槽位 | 含义 | 映射到 describe 输出 | 示例 |
|------|------|---------------------|------|
| `action` | 业务动作 | 匹配 operationId 动词部分 | 训练/分析/查询/导出/发布 |
| `resource` | 业务对象 | 匹配 domain 或 requestBody 关键字段 | 模型资源/数据集/报表主题 |
| 查询口径 | 维度、指标及聚合方式 | 当前资源元数据和查询契约 | 按区域汇总销售额 |
| 查询范围 | 时间、筛选、排序及行数 | 所选场景的有效字段或参数 | 华东、去年、销售额前10 |

仅在操作未知时用业务动作和对象收窄 API；已知接口直接核对契约。查询资源使用目录搜索，不把业务字段当 API 搜索词。

具体请求字段由所选场景及接口契约决定，不把所有筛选都构造成 MQL 条件。API 列表不是业务资源列表；资源定位按 `references/common-core/resource-discovery.md`。

## 槽位缺失处理

| 缺失槽位 | 处理策略 |
|---------|---------|
| `action` 未知 | 让用户补充要做什么（查/导出/创建等） |
| `resource` 未知 | 按业务需求通过已核实的资源搜索接口定位模型/报表，不假设页面预选资源；仅对剩余业务歧义澄清 |
| `dims`/`metrics` 未知 | 从问句和目标资源必要元数据匹配；模型字段树或报表定义按需读取，不能唯一确定业务口径才澄清 |
| `filters` 未知 | 核实用户范围及资源默认筛选；省略参数不等于全部，不能无条件声称不影响结果 |
| `modelId` 未知 | 已确定模型分支时有范围搜索并核实资源身份，唯一匹配直接使用，不默认让用户从全部模型中选择 |
