# 白泽会话与洞察排障

下列会话、轮次和 Agent 图排障仅适用于实际调用了该流程的任务；直接取数不需要为了诊断而新建白泽会话。

## 控制面或认证失败

迹象：

- `createConversation` 失败；
- `queryRpc` 报认证失败；
- 轮次与聊天日志均为空。

检查所选 profile、服务地址、令牌／会话有效性及权限。此时还没有创建 Agent 轮次或沙箱，不能归因于 MQL、Python 或工作流。

## 流传输失败

迹象：

- SSE 连接结束或超时；
- 会话中仍有 `RUNNING` 轮次或后续日志。

用相同 `convId` 调用 `queryRpcResume`，不要创建重复会话或重做可能非幂等的任务。

## Agent 图失败

迹象：

- 轮次已创建；
- 计划产物显示节点失败、未启动，或结束节点一直等待；
- 工具节点返回 `TOOL_EXECUTE_ERROR`。

记录失败节点、轮次状态和工具错误，核对本次Agent及输入是否正确；Agent内部工作流异常报告服务端问题，不修改节点、连线或运行配置来绕过。

## 工具或 OpenAPI 失败

迹象：

- Agent 已到达工具节点；
- 响应为 HTTP 4xx／5xx，或请求体为空、格式错误。

先从本轮日志核对实际调用、请求参数、HTTP 与业务错误。仅当错误明确涉及 Provider 或工具配置，且当前账号可读取时，再核对对应配置；无法取得的信息随错误交给服务端排查，不把读取内部配置作为普通问数的前置。

## 沙箱或数据查询失败

迹象：

- 已有轮次和日志；
- 日志显示 `smartbi_cli`、SQL／MQL、Python 或 Parquet 操作失败。

此时才检查沙箱实际命令、模型／表／字段名、筛选、生成文件和行数。本地 `smartbi` 控制会话；`smartbi_cli` 在白泽沙箱中运行，两者不是同一个可执行程序。

## 结果或展示失败

HTTP 200、轮次 `NORMAL` 或生成文件均不证明业务结果正确。应核对结果行、业务粒度、总额、预期产物，以及任务要求的视觉或版式质量。

## 常见查询与流症状

| 症状 | 可能层级 | 处理 |
|---|---|---|
| 流达到事件上限时轮次仍为 `RUNNING` 且答案为空 | 流传输 | 用更高事件上限恢复同一 `convId` 并检查轮次，不创建重复会话。 |
| `round.answer` 看似不透明 JSON | 结果／展示 | 解析事件数组，合并追加文本，排除推理／工具日志，单独处理文件片段。 |

## 最小诊断信息

按失败层收集已有信息，不包含凭证，不为凑齐清单额外读取内部配置：

- CLI 版本及 profile 名称，不含配置内容；
- 本轮使用的 Agent ID；
- 会话 ID、轮次／查询 ID；
- 轮次状态、耗时及 `errorType`；
- 按失败查询 ID 筛选的日志；
- 日志涉及的 HTTP 与业务错误。

仅节点或工具配置错误补充相关节点／Provider／Tool 标识；仅文件错误补充相关产物的名称、大小及必要哈希。优先复用本轮日志已有内容。

## 资源未训练

`RESOURCE_NOT_TRAINED` 出现在知识或向量检索节点时，表示所选Agent的资源训练前提未满足，不是MQL语法失败，也不证明模型不能直接取数。核实当前Agent所需能力和只读训练状态；不自动训练、重置或修改模型，不反复创建会话。
