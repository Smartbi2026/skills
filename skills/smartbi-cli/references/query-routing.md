# 数据请求路由与模型直接取数

本文件只处理数据类请求；定时、推送、建模、数据源和资源操作按主 Skill 路由。桌面智能体理解问句、解释模型，按资源类型与 SDK 能力构造 MQL、只读 SQL 或指标模型查询，并完成后续分析和展示。CLI 负责调用 SDK。普通取数不依赖模型训练、知识图谱、Baize、会话或 Python，不按训练状态筛选模型。下文 MQL 最小执行链仅针对 `AUGMENTED_DATASET`；新旧指标模型见 `metric-model-query.md`。

模型维度、指标、筛选、分组能由 MQL 正确表达时优先 MQL。用户明确要求 SQL，或 MQL 不适用而 SQL 契约与模型逻辑表、字段、关联、口径信息充分时走 SQL；详见 `data-model-query.md`。SQL 分支仅补齐所需 SQL 元数据，不先试错 MQL，也不以 CGI Overview 为唯一元数据来源。以下最小执行链描述常用 MQL 分支；SQL 分支替换元数据、请求构造及查询接口，复用同样的结果校验与交付规则。

## 数据与洞察路由

先定位查询对象，再选择取数路径。外部智能体没有预选报表/模型清单：用户明确给出资源名称、ID或链接时核实环境、类型和资源身份；仅有“订单”“经营分析”等业务主题时，通过当前环境目录/资源搜索定位合适的模型或报表，不能把同名精确命中直接认作用户指定资源，也不能提前只筛模型而排除报表。搜索结果先本地过滤为可直接取数的模型/报表类型，按名称或别名精确匹配、包含匹配、目录路径匹配的顺序排序并按资源ID去重；最多展示 5 个最相关候选及类型、路径。强候选仍有多个且会改变答案时才澄清；弱匹配过多时先收窄业务主题或目录，不下载全部元数据，也不把原始结果列表交给用户。目录ID先定位其下资源，不当作可查询模型或报表。

普通数据模型问数按下文直接 MQL/只读 SQL；新旧指标模型按 `metric-model-query.md` 选择各自接口或关联的可查询模型。已有报表问数先读 `report-query.md`，优先使用已验证的报表读取/导出能力。服务端内置报表 Skill 仅在能力需要且外部调用契约已核实后使用，不是前置。生成本地分析报告不等于查询已有报表；报表来源不改变后续复杂洞察的路由原则。

用户明确基于已有电子表格、Web 电子表格、仪表盘、即席查询、透视分析等报表资源问数，或只给名称、别名、ID 而目录核实为报表类型时，优先读取该报表的数据；“大屏”一词不使已有仪表盘自动转入白泽。要求新生成综合大屏或复杂洞察时，才按下述白泽分支判断。

用户明确指定“直接取数、不经过AI问数、由桌面智能体分析”或指定白泽时，优先遵循。未指定执行方式时：

- 指标、维度、筛选、分组、排序、TopN、两期比较：按已定位的资源取数，数据模型走 MQL/只读 SQL，新旧指标模型走其专用或关联模型路径，报表走报表分支；同一问句混合累计值、时点值、期间平均值和人均值，但只要求聚合及同比时仍属于直接取数，不因需要拆分口径与本地合并就转白泽。已有数据制图或文件转换由外部智能体整理交付，不因出现 Excel/CSV 就创建会话。
- 正式分析报告、原因归因、预测、行动建议、综合大屏，以及需要服务端业务知识或多工具协同的任务：默认白泽洞察，读取 `sessions-and-logs.md`。大屏或报告仅是已有结果排版时继续本地处理。
- 任务目标已清楚，但难以判断简单或复杂时，可按白泽洞察处理；模型、字段、时间或指标口径有歧义时先补齐，白泽不能替代口径确认。
- 白泽不可用时说明缺少的能力；若直接查询和本地分析能完整满足目标则采用，并说明执行方式。用户指定白泽或缺少不可替代的知识/工具时报告阻塞，不伪称已完成白泽分析。
- 查询错误按请求、权限、数据源或模型语义诊断，不以转白泽掩盖失败。涉及服务端资源创建、修改、发布、推送时仍遵循相应业务操作与授权范围。

## 问句优先，减少调用

先从问句确定指标、维度、时间范围、筛选、粒度及交付形式；仅补问会改变答案的歧义，不要求用户确认接口或整份查询计划。

- 模型 ID 已知就读取并核验该模型，不再搜索目录；模型字段与接口契约在同一环境任务中已确认就复用。冷启动仅补齐必要契约和字段树，后续通常一次 MQL 即可。
- 同一来源、相同过滤粒度的多个指标合并查询。比较两期一次取两期数据；占比取满足分母范围的完整小规模分组，或另取分母，不能拿 TopN 合计代替总体。
- 已确认结果规模适中时，可适度提高本次 limit 一次取齐，避免机械拆成小页；未知规模从有界批量开始并按下方规则确认完整性，不把某次验证的行数写成通用默认值。小表优先直接返回 dataTable，只有需要文件或响应不适合内联时才增加下载步骤。
- 基础数据足够时，增长率、占比和贡献拆解在本地计算，不为了简单四则运算引入临时 MDX、额外元数据接口或会话。跨来源指标只有模型明确支持同粒度组合时才合并，否则分别查询并按确定的键对齐，不能横向强拼。
- 追问只改变展示、排序、图表或文件形式时，复用本轮完整且匹配范围的数据；筛选/时间/粒度变化无法由现有数据精确回答，或用户要求刷新时才再查询。不得从 TopN、截断数据或已聚合数据推导缺失总体、明细或去重数。
- “去年/今年”按当前日期和用户时区解释并在答案中说明范围，不以模型最大日期替代今天。已有明确范围不重复询问。
- 单位、币种、高净值阈值、客户去重口径、存量时点等不能从字段名猜。单位未知可保留模型原值说明；问句涉及“亿元”等单位换算或阈值时，需先确认单位再构造条件。交易记录数不是客户数，净手续费/交易金额不自动等于合同费率。
- 保留金额和数量的原始正负号及小数精度；不能因名称含“金额”就取绝对值，或因名称含“数量”就取整。负值的业务含义以模型口径为据，不能自行解释为退款、亏损或数据错误。
- 已从模型定义和当前数据确认的口径直接复用，不重复澄清。例如余额取期末、峰值取期间最大值时，按目标时间粒度查询；不能把多个期间余额求和，也不能把期末值冒充期间平均。只有用户要求的口径与已知定义不同或定义不足时才补问。
- 名称与定义冲突时明确指出：名为“金额”却配置COUNT、名为“平均值/使用率”却配置SUM，不能直接按名称回答，也不能擅自改成SUM/AVG修正模型。用户明确要“模型原指标值”可带实际口径返回；要求业务金额、均价或比率时先核实所需定义。
- 模型有多个时间角色（如委托日期、交易日期、发货日期）时，按问句对应的业务事件选择字段，不默认使用第一个时间层级。上下文无法确定且会改变结果时只澄清时间口径；两个年度合计偶然相同不证明两种日期可互换。
- 校验应对应问题：总额、占比分母、排序、时间对齐、分组连接放大及是否截断。常规请求只做必要检查；完整回归与额外对账查询只在测试或发现疑点时运行，不把验收矩阵变成每次用户查询的前置。
- 返回业务答案、必要口径和限制即可；通用输出约定中的接口名、命令和追踪信息在取数路径仅按排错/审计需要展示。无记录、空值和零分别表述；技术成功不代表口径正确。
- 字段树中同时出现的维度和指标不保证可正确关联。首次使用跨事实来源维度或出现各组数值完全相同等疑点时，优先与已取的同范围总额对账；必要时增加一次总额/筛选验证。若互斥分组合计放大、每组重复总体或条件未生效，停止交付该分组结论，记录查询与 tid 并说明模型关联/维度适用性待核实。不能靠除以组数、去重金额或改 SQL 掩盖问题。
- 排名、占比中保留空分类贡献，并标注其缺失含义尚待确认；“全部类别第一”和“有名称类别第一”分开说明。不能悄悄剔除空分类改变分母或将空分类虚构成某个业务渠道。

### 混合累计、时点与派生指标

同一问句包含不同事实来源、粒度或可加性的指标时，先按“来源 + 过滤范围 + 聚合语义”分组；同组指标合并查询，不兼容的组分别查询后按明确的期间键对齐。查询次数以得到正确口径所需的最少组数为准，不能为了单次 MQL 强行横向拼接，也不能把这类普通聚合比较升级成白泽洞察。

- 可加的流量/金额指标按目标期间汇总；期初值取首期的期初，期末/时点值取末期对应值。期间平均值仅按模型定义直接查询或由已核实的权重计算，不能把月均值简单求和或无依据地再次平均。
- 人年、去重人数、比率、人均值等非可加指标优先在目标期间粒度直接查询。仅当公式与基础字段定义已核实时，才由完整期间的分子、分母重新计算；不能把各月人年数、人均值或同比相加/平均。模型指标与重算值同时可得时应对账，冲突则停止给出未经证实的业务结论。
- 两期同比必须使用相同期间边界、组织范围、维度和口径；本期与基期分别得到最终聚合值后再计算。基期为零或空时同比保持空值并说明原因，不能用零填充后继续计算。
- 聚合前先区分“全空”和真实零。某指标在目标期间全部为空时，期间结果仍为空；依赖它的本地差额、比率或偏差也保持为空。若模型在基础输入为空时仍返回派生值，只能标注为“模型指标原值”并说明输入缺失，不能把它当作已独立验证的公式结果。
- 用户明确限定某类指标必须使用指定业务维度时，该维度约束属于查询口径。元数据中核对其来源、层级和成员键，相关指标的筛选或分组必须来自该维度；同名的人员部门、归属部门或其他组织维度不能替代。最终校验需记录实际采用的维度角色，仅得到数值但未落实指定维度不能判定场景完成。

## 默认取数范围

- 普通“查询XXX数据”以取齐用户已明确条件与粒度下的结果为目标，不要求额外说“全部”。汇总问题只需完整汇总结果，不拉底层明细；没有明确条件且上下文也无法确定时，只澄清会影响答案的范围，不擅自补成全历史或全字段。
- `limit` 是单次批量。未满批且无服务端截断迹象时校验后结束；满批且无可靠结束证据时，按固定页长和稳定排序继续，直到短页/空页等结束证据成立。不要仅提示“可能截断”就把普通查询当作已经完成，也不为每页重复询问。
- 用户明确“前N条”“TopN”“抽样看看”时，N才是需求上限；满足该范围后停止，不因满N行再取下一页。TopN必须按目标指标排序，必要时加稳定次排序；若还问全体占比或总体合计，另保证分母完整，不能用TopN合计代替。
- 已有完整数据能回答时直接复用，不必为了验证是否还有数据重新请求。未知规模不先固定增加COUNT调用；已知适中规模优先一次取齐，不能以每次都分页作为最简路径。
- 若实际响应大小、查询耗时或运行环境容量表明继续获取不合适，保留已取数据，说明已取范围及未完成原因，再选择缩小范围或受支持的完整导出方式；不能静默停在某个内部行数上限，也不能无界提高limit。文件查询同样必须核对范围，文件格式本身不证明全量。
- 展示可以只给摘要或部分预览，但要区分“已取齐、仅预览N行”和“只取得N行、尚未取齐”。不要为把全表塞进对话而制造重复调用；需要完整交付时采用合适的本地文件或分批展示。

## 最小执行链

1. 环境地址与模型资源ID必须匹配。跨实例或链接服务器模型以目标环境返回的资源映射为准，不直接沿用源实例ID或猜测远程ID前缀。网页登录账号不等于CLI个人令牌；缺少目标环境凭证时只补该凭证，不挪用其他环境令牌，也不以页面登录成功或公开registry可访问宣称取数成功。复用指定或默认 profile；有效配置不重复初始化。无配置按 `init.md` 引导。所有命令带 `--profile`。
2. 用户提供资源ID时先核实资源类型；目录ID应定位目录下的模型，不能直接当模型查询。字段树返回空时先核对资源类别、环境和可见性，不能判定模型无数据。用户提供或上下文已确定模型 ID 时验证复用；否则通过普通目录接口定位。用户明确把某段文字作为资源名称/别名时，若当前契约支持，可用 `catalogtree.searchCatalogTree` 的 `queryMode: "EXACT", matchField: "ANY"` 一次匹配，精确无结果且可能为简称时才做一次有范围的模糊搜索。用户只描述业务主题时，先利用客户/目录/业务域上下文收窄，再做有范围的模糊搜索；没有可用范围且全局搜索过宽时先澄清范围。搜索可能返回命中字段、父目录、任务、计划等大量关联项：先保留当前接口可查询的模型和报表资源类型，按名称/别名精确、名称/别名包含、路径包含排序，按资源ID去重，只保留最多 5 个强候选用于消歧。同名目录、任务和计划不是模型，不能取搜索结果第一项；`MT_MODEL` 等不能被当前增强数据集接口直接识别的类型应走 `metric-model-query.md` 的新指标模型路径；`TABULAR_DATASET` 走旧指标模型路径，不能因同一接口不支持就排除其取数能力。仍有多个强候选才澄清，不逐个读取所有候选元数据；没有强候选时收窄业务主题或目录。普通目录搜索可能不包含链接服务器资源；使用当前环境提供的远程资源目录或明确的资源映射，不能猜远程ID前缀。已有白泽资源清单可作为映射线索，但其训练状态不能成为直接取数的要求，也不能认为该清单列出了所有可查询模型。空结果只说明当前环境/权限/条件下未找到，不能断言系统不存在，也不转训练资源列表。
3. 优先使用当前环境已注册、能提供所需字段与口径的模型 Overview；已取得充分信息则不重复读取字段树。Overview 不可用或简单查询只需字段时调用 `datamodel.getDataModelTrees`，请求体为 `{"modelIds":["<id>"]}`，定位可用维度、指标及来源，同一任务复用。字段节点按type、字段语义和children共同识别，不以leaf=true为唯一条件；远程节点可能没有dataType或将末级字段标为leaf=false。数值字段为FIELD不等于已定义可加度量，预算/实际行、累计值和比率须保持业务粒度，不自动提升为SUM指标。字段树不保证包含公式、关联关系和全局参数；需要这些信息时，若当前环境支持，可按契约调用 `tabularmodel.getDataSet`（`{"req":{"dataSetId":"<id>"}}`），从完整定义核对 views、relations、measures、parameters。不是每题都读取完整模型，MQL 不以 CGI Overview 为前置。
4. 根据问句构造 `req` 外层的 MQL 请求，详见 `data-model-query.md`。需要from时取目标指标所属来源；模型级跨来源计算指标按公式与契约可省略from，不能虚构单一来源。字段标识按当前模型契约解析，label、技术名、SQL 列名不能无条件互换。日期格式不明确时用有界样本确认。定义了全局参数必须完整传入。
5. 数据查询场景的只读调用采用最短可验证调用链：已知 operationKey 且本任务已核实契约时直接 call；已知 operationKey 但契约尚未核实时执行 describe → call；describe 信息不足才补 doc；不知道 operationKey 时才执行 list/search → describe → call。目标环境、CLI 版本或接口契约变化后重新核实，不能跨环境沿用。调用 `datamodel.queryDataByMql` 时按问题设置过滤、排序和单次批量limit，并按上方“默认取数范围”规则取齐目标结果；不默认全字段或 50 万行。临时请求使用 UTF-8 JSON 文件和 `-d "@<absolute-path>"`。
6. 检查 CLI ok、业务 success、error、列、`dataTable.data` 实际行数和 rowCount。非空 s3Url 通过当前契约支持的下载接口获取，检查真实文件类型而非只看后缀。无 s3Url 时按实际返回行数与请求的 limit/offset 判断分页；rowCount 的含义须由当前接口实测或契约确认，不能要求它必等于本页行数。上述范围规则同时适用于直接展示和文件导出。
7. 交付模型、口径、过滤、粒度、行数和结果/文件路径；分析、图表、报告、大屏由桌面智能体完成。不要暴露 token 或签名 URL。

目录可见只证明资源可发现，不证明当前查询接口支持该模型类型。批量读取元数据只合并已知受当前接口支持的类型；若批次明确报某个ID/类型不支持，隔离该项后读取其余项，不将整批当成无数据，也不逐项重复全部调用。对不支持类型只按当前已注册的只读能力查找替代元数据路径，不伪装成AUGMENTED_DATASET、改模型或转AI问数。一个模型不支持某接口，不应扩大为所有同类模型或整个SDK永远不支持。

## 路由与口径

- 报告、归因、大屏按上方“数据与洞察路由”选择执行方式；显式报表、调度或推送操作走相应业务接口。
- 查询失败先区分请求错误、模型语义问题、权限与服务异常；不能仅凭报错自动转 SQL、训练或 Baize。SQL 也必须保持模型指标口径，不能猜测关联或绕过模型治理。
- 直接 MQL 仍可能聚合。金额/数量确认可加性后汇总；同比、比率、进度、单价需明确模型计算口径及粒度。不能自动 SUM/AVG，不能用 MAX/ATTR 或全维度来替代口径确认。信息不足时澄清。
- 不自动按月分批并拼接聚合结果：比率、去重计数、TopN 等通常不能直接合并。必须先证明分批保持原查询语义。

## 可移植执行

复用 npm 全局 CLI 和 profile，不写死地址、桌面客户端目录或 APPDATA。Shell 解析 smartbi；Windows 子进程从 PATH 解析 smartbi.cmd。请求用系统临时目录并在 finally 清理，结果放用户工作目录，Skill 目录不写入缓存/业务数据。Python/pandas 仅按文件读取或转换需要加载，不作为 MQL 调用前置。

不新增模型元数据、查询结果或失败记录的持久化缓存，不打包项目地址、凭证、资源ID、字段映射或测试产物；同一任务仅复用上下文中已确认的信息，环境/身份/字段变化时重新获取。CLI 自身的 API registry 缓存由 CLI 管理，不作为 Skill 自带数据或客户配置。字段错误先检查元数据，不按报错候选猜业务映射。网络/数据源/权限错误按实际原因报告，重试遵循主 Skill 的幂等规则。

同一环境、同一任务已经证实失败或数值异常的能力/字段组合，保留失败原因和影响范围；后续同类问句复用该诊断，直到相关定义、版本、权限或输入发生变化。不要重复执行相同失败探测，也不要把单模型结论推广为其他模型的永久限制。

## 结果兼容性与完整性

先核对当前接口是否将 dataTable 定义为预览、是否存在截断标记、完整结果文件或分页。明确为预览时不能按行数短于limit断言完整；按契约下载完整文件或分页。文件也须校验范围和真实格式，不固定为Parquet。

- 普通取数默认直接展示已校验的 `dataTable` 或业务摘要，不强制导出 CSV。用户需要文件时才选择相应格式；大结果可逐页交付，每页标注已取范围及“尚未取齐”，汇总、占比和最终结论等完整性校验通过后再交付。
- `rowCount` 不能直接当作本页行数或可交付行数：有接口会在分页响应中返回大于本页实际行数的计数。按 `dataTable.data` 的实际行数推进分页；若 rowCount 在当前契约中表示总量，可用于交叉核对，但仍以稳定排序、去重和终止条件验证完整性。达到 `limit` 时不能断言完整，即使刚好等于实际总数，也需按分页规则确认结束。
- 流式能力以当前接口 `describe` 为准。已验证的直接 MQL/SQL 接口为 `streaming=false`、`application/json`，一次请求返回一个结果对象；客户端逐页展示、CLI/HTTP传输分块均不等于原生逐行数据流，不为流式展示引入 Baize。小结果一次取齐通常调用更少，不能为了“流式”机械拆页。
- `dataTable` 可能返回带千分位、科学计数法或已舍入的数字字符串。结合字段类型和格式转换，保留原值；空值不能变成 0，编码不能转成数值。百分号需识别比例尺度，高精度计算优先使用未舍入的基础数据。
- 时间层级的显示值不保证等于筛选使用的成员键；已知存在的月份筛选却返回空时，核对当前成员/层级契约，不能盲试日期格式或断言无数据。已取齐目标范围且可准确本地筛选时可复用，并说明筛选执行位置。
- 若分页短页/空页与已确认的更大同范围结果矛盾，完整性检查失败；不能仅因收到空页就宣称全量，也不能将不同调用的部分页随意拼接。
- 空白显示值不一定是空字符串，也可能来自 NULL。过滤必须区分 `IS NULL` 与 `= ''`，不能只凭展示值构造条件。
- MQL 条件支持范围以当前模型的实际执行能力为准，SQL 风格的条件描述不代表所有运算符均可用。若远程/旧版模型明确拒绝 OR，同一字段的多个等值条件可在语义等价且当前接口支持时改为 IN；不能把跨字段 OR 改成 AND，也不能随意拆查后拼接聚合结果。IS NULL 报错不能解释为无记录或改成空字符串过滤。已有完整且粒度适合的数据可以精确本地筛选，并说明处理位置；否则报告未完成及具体限制。
- 顺序分页保持查询、页长和唯一稳定排序不变，使用 `offset = 页序号 × limit`。先校验相邻页实际语义；某些环境会把非整页 offset 按页边界处理，不能承诺任意行偏移。检测重复页/重复键，短页或空页结束，并对账；恰好整页需再探下一页。数据变化或无法证明完整时明确限制，不宣称全量。
- 文件按实际内容识别；`showDataTable=false` 的产物可能是 XLSX，不保证 Parquet。回读文件并核对表头、行数和数值后才交付。
- `getMetadataFromMql` 是按需补充口径的接口，须先 describe；其业务失败不等于直接取数不可用，但仍缺少的口径不能编造。同比/环比等时间计算须按实际输出精度复算，缺基期保持空值。
- 发现未来日期时明确数据范围，不能当作已经发生的业绩；增长贡献拆解不等于因果证明。
